From a key press to the screen

The wx side: what starts when the program starts, how the window is laid out, and how one key goes through the editor, the model and the painter.

Built from the as-built docs at commit 959bc3c (dev, 2026-10-31), updated from them after the bug fixes of the same day. When the code changes, the page is rebuilt from the docs.

Click a box (or Tab to it and press Enter) to see what it is, its files and what it hands to whom.

One key press traced

The cursor is in an Action line and you press a.

  1. wx sends EVT_CHAR to the focused MyCtrl; OnKeyChar reads the key code (util.eventKeyCode).
  2. No keyboard command is bound to a (other keys go through gd.mainFrame.kbdCommands to a menu handler or a cmd<Name>), so the plain character goes to sp.addCharCmd.
  3. The model inserts it and re-wraps the paragraph (see the model).
  4. The editor runs cmdPost, re-paginates on a timer, makes the cursor's line visible and calls updateScreen: the status area shows the element type, the act panel and the bible panel's scene line are refreshed.
  5. Refresh() leads to OnPaint, which asks the view mode for the visible texts and draws them; in Action, a run of capitals you are still typing is not underlined until a space or punctuation ends it.

Where the film shows in the window

The bible panel and the Script menu's film commands (Annotate, Sync to spec on F5, Review proposals) always work on the current tab's film: MyFrame.filmOf(ctrl) finds the open film whose script part is that tab's file. A script that belongs to no film shows a line saying so in the panel.

Check yourself

Why does the act panel not change size when you zoom?
It draws with its own pixel fonts, not the editor's zoomed fonts, and it does not scroll.
A click lands between two lines in layout view. Who decides which line it is?
The active view mode's pos2linecol: each mode knows where it drew each line. The editor then sets sp.line and sp.column.
Typed text accepts only Latin-1. Does pasted text?
No filter there: paste, import and find/replace do not go through isValidInputChar, so other characters can reach the script. Helvetica and Times measure them like ?.
