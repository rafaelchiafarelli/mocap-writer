A script is a flat list of lines

Trelby keeps no tree of scenes and elements. The script is one Python list of Line objects, already wrapped to the page width. Elements, scenes and pages are all worked out from that list.

Built from the as-built docs at commit 959bc3c (dev, 2026-10-31). When the code changes, the page is rebuilt from the docs.

Click a box (or Tab to it and press Enter) to see what it is, its files and what it hands to whom.

The line breaks

lbValueMeans
LB_SPACE1the paragraph goes on; a space joins this line to the next when the text is exported
LB_SPACE22the same with two spaces (after a sentence)
LB_NONE3the paragraph goes on with nothing between (a long word split)
LB_FORCED4a line break typed inside the element (Shift+Enter)
LB_LAST5the element ends here

One command traced: typing a character

  1. The editor's OnKeyChar gets the key; it is not a keyboard command, so it calls sp.addCharCmd with a CommandState.
  2. addCharCmd inserts the character at sp.column in sp.lines[sp.line].text, after its typing rules: auto-capitalizing (a sentence's start, a lone i), INT. or EXT. turning the element into a Scene, ( turning it into a Paren.
  3. The paragraph is re-wrapped (rewrapPara), so a word that no longer fits moves to the next line and the cursor follows it.
  4. The edit is one SinglePara undo step: the paragraph's lines before and after.
  5. Back in the editor: cmdPost, re-pagination on a timer, the cursor's line scrolled into view, and updateScreen repaints.

Check yourself

Why does undo store lines as strings?
str(line) is the line-break char, the type char, the number between markers and the text: compact, and zlib-compressed when shorter, so a long undo chain costs little memory. It also carries the scene number, so undo restores numbers.
A paragraph of Action becomes longer than the page width. What changes in sp.lines?
Re-wrapping splits it into more lines: the old last line gets LB_SPACE (or LB_NONE inside a long word) and a new line with LB_LAST is inserted after it. The element is still one element.
Why must applyCfg clear the undo chain?
Changing element widths re-wraps every paragraph (reformatAll), so the stored line lists of old undo steps no longer match the script. reformatAll even asserts there is no undo history.
