Green · the film root and its records

A film is a folder of small, checked files

Everything about a film that is not script text lives in JSON files beside script.fountain, each one a mocap-contracts message. The writer owns most of them; agents get their own space.

Built from the as-built docs at commit 959bc3c (dev, 2026-10-31), updated from them after the bug fixes of the same day. When the code changes, the page is rebuilt from the docs.

Click a box (or Tab to it and press Enter) to see what it is, its files and what it hands to whom.

Why a Harpia contract and not a private format

Mocap Studio's rule is that applications talk through Harpia: the formats are .harpia files in mocap-contracts, generated into Python (and Java for the camera app), with the rules required cannot express in mocap_contracts/rules.py. The writer and the pre-production agents import the same package at the same tag, so a field means the same in both, an invalid file is refused on read by everyone, and changing a format is a reviewed change in one place. A private JSON written by the writer alone would drift the first time an agent read it.

Find props traced, from the menu to the files

  1. Bible panel → From script… → Find props calls OnFindProps.
  2. biblelinks.propPlan(b, sp) reads the Action lines of every numbered scene: each run of capitalized words (propwords.find_prop_words) that is not a speaker, not a bible character and not marked "not a prop" is a link to a known prop, or a new prop with its scenes.
  3. The checklist shows known props ticked and new ones unticked; nothing is written until OK.
  4. For each new prop, Bible.create asks film.newId("prop"), which writes ids/w.json first, picks a free folder slug and writes bible/props/<slug>/item.json; Bible.link adds its scenes.
  5. Each write goes through Film.writeText: ownership checked, written atomically through a temp file, and one line appended to history/2026-10.jsonl.
  6. The props left unticked can be marked "not a prop": bible/not-props.json, also logged.

Check yourself

An agent writes a proposal. Can it write into bible/ directly?
Not through the writer's checks: bible/ is owned by the writer. An agent gets its own id space and a proposals-<code> part (Film.addSpace). How agents deliver proposals is still an open decision in mocap-preprod.
A photo of a set was moved outside the program. What happens on Open film?
The item opens; the missing file is a problem with a relink reference, listed in RelinkDlg, where the creator can search for it. A found new location is offered for the other missing files that moved the same way.
Why are bible/scene-index.json and bible/sync/ left out of the change log?
They are built from the script by code and never edited, so logging them would only fill the history with copies of the index (Film.derived).
